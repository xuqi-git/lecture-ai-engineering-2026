## 実装課題

`--chat` を指定すると、同一セッション内の会話履歴をリストで保持します。新しい質問を過去の質問・回答とともに API に渡し、応答が成功した後にだけ新しい往復を履歴へ追加します。API エラーや空応答で不完全な履歴を追加しない設計です。

| 時点 | API に渡す内容 | 成功後の履歴 |
|---|---|---|
| 第1回 | 質問1 | 質問1、回答1 |
| 第2回 | 質問1、回答1、質問2 | 質問1、回答1、質問2、回答2 |
| 失敗時 | それまでの履歴と新しい質問 | 直前の履歴を保持 |

Gemini の `user/model` と DeepSeek の `user/assistant` の役割表現を変換し、両 API に対応しました。DeepSeek では共通の非思考モード、出力上限2048 Tokenを指定します。会話履歴はメモリ内に保持し、プログラムを終了すると消えます。

### 実行方法

```bash
uv sync --frozen --python 3.12
uv run python -m app.ask --chat --provider deepseek --model deepseek-flash "LoRAとは何ですか？"
# 次の入力欄で「それを具体例で説明してください」などを質問
# /exit または /quit、空入力、EOF で終了
```

`DEEPSEEK_API_KEY` は本人の既存設定からプロセス環境に渡します。キーはコード、コミット、ログに保存しません。Gemini の場合は `--provider gemini` と `GEMINI_API_KEY` を使用します。

## 検証結果

Python 3.12.14、講座の固定依存関係で `uv run pytest -q` を実行し、**30件が通過**しました（既存11件＋追加19件）。

会話履歴については、テスト用の応答を使って、2回目の呼び出しに前回の質問・回答と今回の質問が順番どおり渡ること、成功後に履歴が4件になること、失敗した質問で履歴が増えないことを確認しました。DeepSeek 用の role 変換も確認しました。

これはオフラインの構造的な検証です。実モデルが前の会話を正しく理解・利用するかについて、生成 API による検証はまだ行っていません。API のモデル一覧取得には成功しましたが、これは対話や生成の検証とは別です。
